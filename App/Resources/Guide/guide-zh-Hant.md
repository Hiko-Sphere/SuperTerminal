## 第一次連線

在連線清單中點一下 **+**，貼上位址即可。它會被自動拆解：`deploy@build.example.com:2222`、`ssh://deploy@host:2222` 與 `[2001:db8::1]:22` 都可以。連接埠留空表示 22。使用者名稱留空則會在每次開啟連線時詢問——對於多人以不同帳號登入的機器，這正是您需要的。

第一次連線時，伺服器會出示它的 host key fingerprint，在您確認之前不會發生任何事。這項核對由您完成——請見 **Host key**。確認之後它就會被記住。

連線畫面上的其他項目都有堪用的預設值。您可以只填一個位址就儲存連線，其餘的以後再說。

<!-- topic: signing-in -->
## 登入

Apex Terminal 會依伺服器預期的順序提供您已設定的憑據，必要時改為詢問：

- **私密金鑰。** 在 **私密金鑰** 中選一把。金鑰絕不離開裝置。
- **密碼。** 開啟 **提供密碼**。欄位留空即改為每次詢問，而不是儲存它。
- **伺服器提出的問題。** 有些伺服器不接受密碼，而是發問——一次性驗證碼、權杖、因過期而必須更換的密碼。Apex Terminal 會逐字顯示伺服器所問的內容，並將您輸入的內容原樣送回。這些回答絕不儲存。
- **什麼都沒設定。** 既沒有金鑰也沒有選擇密碼時，本應用程式會詢問伺服器接受什麼，並只就伺服器真正接受的方式向您提示。

若您的金鑰旁附有 OpenSSH 憑證，會先提供憑證、再提供純金鑰，於是信任您 CA 的伺服器不必看過您的金鑰就能放行。

<!-- topic: keys -->
## 本裝置上的金鑰

**設定 → 金鑰** 是它們所在之處。您可以產生金鑰，也可以匯入金鑰。

產生時有一個真正重要的選擇：

| 類型 | 私密部分存放於何處 | 取捨 |
| --- | --- | --- |
| Ed25519 或 ECDSA P-256 | 本裝置的 Keychain | 可以備份，並透過備份檔案複製到另一台裝置 |
| Secure Enclave（P-256） | Secure Enclave 內部 | 無法匯出、無法備份、無法複製——本應用程式不能，任何人都不能。裝置一旦遺失，金鑰即隨之消失 |

Secure Enclave 金鑰可設定為**每一次簽章**都需要 Face ID 或 Touch ID，也就是每一次使用它的連線。這是硬體所能提供的最強選項，也是保護重要目標的那把金鑰應當選擇的方式。

匯入支援 OpenSSH 私密金鑰，包括受密語保護者（`ssh-rsa`、`ecdsa-sha2-nistp256`、`ssh-ed25519`）。密語只用於解開金鑰這一次，不會被保留。

每把金鑰的公開部分都可以從金鑰清單複製，那正是您要貼到伺服器 `authorized_keys` 中的內容。

<!-- topic: agent-forwarding -->
## 讓伺服器使用您的金鑰

代理轉發——連線上的 **讓這台伺服器使用我的金鑰**——允許在伺服器上執行的程式請求*您的裝置*進行簽章，於是您可以從這台伺服器的 shell 前往第二台伺服器，或存取某個 Git 遠端。金鑰本身不會前往任何地方。

它預設關閉，對於不由您掌控的機器也應保持關閉。在您連線期間，該伺服器上以 root 身分執行的任何程式都可以請求您的裝置簽章，用途不限，包括連往您所使用的其他伺服器。它讀不到金鑰，中斷連線的那一刻簽章即停止——但只要工作階段還開著，那台伺服器就能以您的身分行事。

只有該連線已在使用的那把金鑰會被提供。裝置上的其他任何東西都無法觸及。

<!-- topic: host-keys -->
## Host key 及其變更的意義

每台伺服器都以 host key 證明自己的身分。首次連線時沒有任何可比對的對象，因此本應用程式會顯示 fingerprint 並由您決定——與伺服器管理者公布的內容核對，或與您已經信任的機器上 `ssh-keyscan` 的輸出核對。

此後該金鑰會被記入 **設定 → 已知主機**，而金鑰已變更的伺服器會被**拒絕**。連線會在您的密碼或金鑰被提供之前停止。沒有任何設定可以略過這項檢查。

金鑰變更有兩種常見原因：伺服器被重建了，或您看到的 fingerprint 屬於別人。Apex Terminal 無法分辨這兩者，也不會猜測。若您確知伺服器被重建，請在 **已知主機** 中移除舊項目，然後有意識地接受新金鑰。

**受信任的授權單位** 是這件事的另一半。加入某個 CA 的公開金鑰之後，由它簽發的每一把 host key 都會被接受，不需逐台主機決定——這是管理整片機群而不累積一堆 fingerprint 的標準做法。

<!-- topic: cloudflare -->
## Cloudflare Access 與 Tunnel

透過 Cloudflare Tunnel 發布的伺服器沒有可供連線的開放 SSH 連接埠。開啟 **透過 Cloudflare Tunnel**，Apex Terminal 會自行建立隧道——不需安裝 `cloudflared`，也不需在旁邊執行任何東西。

兩種登入方式：

- **瀏覽器登入** 會在系統瀏覽器中開啟 Cloudflare Access，您在那裡使用貴組織所採用的身分提供者。權杖以密封形式回到本應用程式，存放於本裝置的 Keychain，且僅用於該主機名稱。
- **服務權杖** 不需瀏覽器即可登入。請在 Cloudflare Zero Trust → Access → Service Auth 中建立，並在該應用程式的政策中允許它。它保存在 Keychain 中，絕不同步，並隨連線一併刪除。

Cloudflare 連線失敗時，錯誤通常來自 Access 而非 SSH，因此 **Access 診斷** 會直接針對該主機名稱檢查，並告訴您它發現了什麼：該主機名稱是否確實位於 Access 之後、該應用程式提供哪些登入方式、本裝置持有的權杖是否仍然有效以及何時到期。它也可以只登出該應用程式，而不影響您其他的 Cloudflare 工作階段。

**設定 → 登出所有 Cloudflare Access 應用程式** 會清除裝置上的每一個權杖。

<!-- topic: jump-hosts -->
## 經由另一台伺服器抵達

無法直接連線的伺服器，可以經由連得到的伺服器抵達。在連線上加入跳板主機，它們會依序使用：先連到第一台，透過它開啟通往第二台的通道，依此類推直到目的地。

每一段都以自己的身分驗證，使用各自的金鑰或密碼；每一段的 host key 都與其他任何連線一樣接受檢查。不會因為某條連線只是中間環節就放寬任何要求。

## 終端機

完整的 xterm-256color 模擬、全彩、寬字元與組合字元，回捲行數可在 **設定 → 終端機** 中設定。

在手機上，或在沒有硬體鍵盤的 iPad 上，鍵盤上方那一列提供觸控鍵盤所沒有的按鍵：Control、Escape、Tab、方向鍵。點一下 **Control** 會為下一個按鍵鎖定，因此先按 Control 再按 C 會送出 `^C`。長按可持續按住。

- **選取文字**：觸控並按住；可用兩端的控制點擴大選取範圍。
- **尋找**：⌘F，或從工具列進入——相符處會標示，並可逐一跳轉。
- **貼上**：超過一行的文字在送出前會請求確認，以免誤入剪貼簿的內容執行了您沒讀過的指令。該檢查可以關閉。
- **文字大小**：⌘+（或 ⌘=）與 ⌘−，⌘0 回到原始大小。
- **字體** 位於 **設定 → 外觀**：可選擇裝置上任何等寬字體，調整行高讓長輸出更寬鬆或更緊湊，字體本身有連字時也可開啟。只提供每個字元等寬的字體，因為終端機繪製的是格線。更改其中任何一項都會重新測量畫面並告知伺服器，因此全螢幕程式的尺寸始終正確。控制項下方的範例會以終端機將採用的相同字體與相同列高繪製，因此在離開該頁面之前就能分辨 `0` 與 `O`。
- **分割畫面**：⌘D 向右、⇧⌘D 向下，在新窗格中開啟同一台伺服器的另一個 shell。**⌥⌘D——或工作階段選單中的「分割並選擇…」——會詢問要放什麼**：另一台伺服器、一個資料夾、透過 VNC 檢視某台機器的螢幕、已經開啟的某一項，或者尚未加入列表的伺服器（此時會開啟編輯器，儲存後直接放入該窗格）。⌥⌘[ 與 ⌥⌘] 在窗格間移動，⌥⌘W 關閉目前窗格。
- **佈景主題** 以及跟隨系統的淺色/深色設定位於 **設定 → 外觀**。
- 當 shell 提供 **shell 整合** 時，本應用程式會理解它：跟隨 shell 回報的工作目錄，並知道提示符與其輸出從何處開始。程式也可以請求複製到您的剪貼簿——`tmux` 與 `vim` 就會這麼做——在您於 **設定 → 安全性** 中允許之前，該功能處於關閉狀態。讀取您的剪貼簿則從不被允許。
- 程式繪製的**圖片**會顯示在格線中：**sixel**（`img2sixel`、`gnuplot`、`lsix` 輸出的格式）、**Kitty** 圖形協定，以及 **iTerm2** 的內嵌圖片。它們會隨文字一起捲動；被其他內容覆蓋時、或視窗寬度改變時會消失——重新換行後的行是另一組儲存格。本應用程式也會把儲存格的像素尺寸告知伺服器，程式據此才能把圖片畫成合適的大小。有兩種傳輸方式會被拒絕，其原因值得說明：Kitty 也允許以*檔案路徑*、暫存檔或共用記憶體傳遞圖片，而那些指的是執行該程式那台機器的檔案系統——透過連線時那是伺服器，因此這類請求會明確回覆 `ENOTSUPPORTED`，而不是默默丟棄。iTerm2 的 `File=` 若沒有 `inline=1`，就是請求把*伺服器選定的檔案*儲存到您的裝置上，本應用程式不會這麼做。

若連線中斷且 **自動重新連線** 已開啟，網路恢復後它會自行恢復。您的回捲內容會保留，新的 shell 會在終端機中標示出來——它從頭開始，位於主目錄，沒有任何正在執行的程式。看起來像是弄丟了工作的 shell 其實沒有：那些工作在舊連線上，而舊連線已經不在了。

<!-- topic: panes -->
## 一個畫面中的多個窗格

一個工作階段可以分割，於是同時看得到不只一樣東西——兩個 shell、一個 shell 加一個遠端畫面、四個 shell，視空間而定。

| 操作 | 按鍵 |
| --- | --- |
| 向右分割 | ⌘D |
| 向下分割 | ⇧⌘D |
| 關閉此窗格 | ⌥⌘W |
| 下一個窗格 | ⌥⌘] |
| 上一個窗格 | ⌥⌘[ |

沒有硬體鍵盤時，同樣的指令位於工具列的 **工作階段** 選單中。手機與 iPad 上都可以分割；在手機上，各個窗格共用一個工具列，而它屬於目前取得焦點的那個窗格。拖曳兩個窗格之間的分隔線可改變空間分配；窗格不會被拖到消失。取得焦點的窗格帶有強調色邊框，VoiceOver 也會朗讀它處於焦點狀態。

在清單中點選某條連線會取代目前的版面，而不是往裡面添加——分割是一個刻意的動作，不該因為您開啟了什麼就自動發生。

<!-- topic: tmux -->
## tmux

為某條連線開啟 **連線至 tmux**，之後開啟它就會接上伺服器上的 tmux 工作階段，而不是啟動一般 shell；若該工作階段不存在則會被建立。中斷連線後，其中執行的內容會繼續執行；換一台裝置再開啟這條連線，您會看到它停在您離開時的樣子。

在 tmux 工作階段中，*伺服器* 擁有版面。畫面上的窗格就是 tmux 自己的視窗與窗格，依 tmux 所說的位置繪製，因此您在筆記型電腦上排好的版面，在這裡看到的就是同一個。工具列中的 **tmux** 選單可以列出視窗、新增視窗、分割與關閉窗格，以及中離但保留。

- **中離但保留** 會讓一切繼續執行。它與意外斷線不同，也是結束一次使用的正常方式。
- 工作階段名稱在該連線的設定中。留空表示 `apex`；填寫名稱可以把不同的工作分開。
- 伺服器上必須安裝 tmux。若沒有，本應用程式會據實說明，而不會把您丟進一個您並未要求的 shell。

本應用程式自己的分割窗格（⌘D）用於一般工作階段。在 tmux 中請使用 tmux 的——兩者同時決定同一套版面只會互相打架，而最終是伺服器說了算。

<!-- topic: sessions -->
## 工作階段與重複使用的連線

您開啟的每條連線都是一個工作階段，列在側邊欄中，並可用 ⌘1 至 ⌘9、⌘] 與 ⌘[ 前往。⌘W 會關閉您正在看的那一個。

在一台已連線的伺服器上開啟第二個工作階段，並不會建立第二條連線。只要各項條件一致——相同的主機與連接埠、相同的使用者名稱、相同的金鑰或密碼、相同的跳板主機、相同的隧道——Apex Terminal 就會重複使用已經建立的那一條。這表示一次身分驗證而非兩次、一次 Face ID 而非兩次，伺服器也只需記錄一條連線。同一台伺服器上的 shell、檔案瀏覽器與連接埠轉發共用它。

上述任何一項有所不同，您就會得到一條獨立的連線，因為以另一個身分驗證過的連線並不是同一條連線。當最後一個使用者關閉之後，它會被短暫保留以備您立刻回來，隨後關閉。

<!-- topic: files -->
## 檔案

每條連線都附有檔案瀏覽器：SFTP 走在同一條連線上，不需另行登入。

- 瀏覽、依名稱/大小/日期排序，並用工具列回到上一層。
- **同時開啟多個資料夾。** 每個瀏覽器都是獨立的工作階段，列在**已開啟的檔案瀏覽器**中，因此您可以在同一台伺服器上或不同伺服器上同時開啟兩個；在 iPad 上還可以把它們分別放進兩個分割窗格，並在其間拖放。
- **上傳** 可來自 iOS 能存取的任何位置；**下載** 到「檔案」App；**快速查看** 讓您不必先下載就能閱讀。
- 重新命名、刪除、新增資料夾並編輯權限——權限同時以讀/寫/執行格線與八進位數字顯示，兩者保持一致。
- 傳輸在一個可查看的佇列中進行，逐一檔案顯示進度，切換資料夾也不會中斷。

為某條連線開啟 **在「檔案」App 中顯示**，該伺服器就會出現在「檔案」App 中，與 iCloud 雲碟並列——於是任何能開啟文件的 App 都能開啟您伺服器上的文件。相應的憑據保存在本應用程式自己的 Keychain 存取群組中；該擴充功能取得的權限不會超過它所需要的。

<!-- topic: forwarding -->
## 連接埠轉發

連線上的 **連接埠轉發** 提供 `ssh` 所具備的三種轉發，意義完全相同：

| 類型 | 作用 |
| --- | --- |
| 本機 | 將本裝置上的一個連接埠轉發到伺服器能存取的某個位址 |
| 遠端 | 將伺服器上的一個連接埠轉發回本裝置能存取的某個位址 |
| 動態（SOCKS5） | 在本裝置上提供 SOCKS5 代理，流量經由伺服器 |

本機轉發與動態轉發在本裝置上監聽，因此裝置上的任何程式——瀏覽器、您正在測試的 App——都能使用它們。遠端轉發在伺服器上監聽；除非其 `sshd` 設定了 `GatewayPorts`，否則它只能繫結 `127.0.0.1`，要求繫結其他位址會被伺服器拒絕，而不是被本應用程式拒絕。連接埠填 0 表示由伺服器選擇，轉發建立後會顯示它所選的連接埠。

每條轉發都會顯示它是否正在監聽、繫結於何處、目前有多少條連線經過它，以及已傳送與接收了多少資料。轉發只在本應用程式執行且該連線開啟時有效。

<!-- topic: screens -->
## 遠端畫面

畫面是透過 VNC 呈現的完整桌面，並且可以走在 SSH 連線內部，因此不需要向網路暴露任何東西。**連線方式** 提供三條路徑：**透過 SSH**（在您已有的連線內部開一個通道）、**Cloudflare**（經由隧道，與終端機相同），或對已經連得到的伺服器使用 **直接連線**。

觸控操作符合直覺：點一下即按一下，按住即拖曳，雙指捲動，兩指外推可放大檢視大型桌面的某個角落——放大之後，雙指改為平移畫面。硬體鍵盤與觸控式軌跡板或滑鼠都以其本來的方式運作。

身分驗證依伺服器所提供的方式進行——經典的 VNC 密碼，或 VeNCrypt 的 plain 與 VNC 驗證子類型。只有在伺服器需要登入某個帳號時才需要使用者名稱：共享畫面的 Mac，或使用 VeNCrypt 的伺服器。密碼保存在本裝置的 Keychain 中，絕不出現在畫面的記錄裡；留空則在開啟畫面時詢問。

不支援 VeNCrypt 自帶的 TLS 子類型。當伺服器只提供這些時，本應用程式會據實說明，而不會退回到更弱的方式。

<!-- topic: snippets -->
## 指令片段與指令面板

指令片段就是您不想再重複輸入的指令。在 **設定 → 指令片段** 中儲存，之後在任何工作階段中一點即用。

⌘K 開啟指令面板，它會同時搜尋您已開啟的工作階段、您的連線、指令片段與每一個動作。輸入其中任一項的幾個字；按 Return 即執行第一筆結果。

**記錄指令歷史** 預設關閉。開啟後，您執行過的指令會再次提供給您；關閉則會刪除已記錄的內容。它只儲存在本裝置上，絕不同步。

<!-- topic: links -->
## 連結、搜尋與捷徑

不必先開啟 App 就能抵達某條連線的三種方式。

**連結。** `ssh://deploy@build.example.com:2222` 會開啟那台伺服器；`apexterminal://open?host=Web` 依名稱開啟一條已儲存的連線。連結也可以攜帶指令——`apexterminal://run?host=Web&command=uptime`——本應用程式在這裡格外謹慎：任何攜帶指令的連結，以及任何指向您尚未儲存之伺服器的連結，都會先展示給您，明確列出伺服器與指令。在您允許之前不會送出任何內容；連結也絕不能自行往您的清單中新增連線——它只填好欄位，是否儲存由您決定。

**Spotlight。** 在設定中開啟 **在 Spotlight 中尋找連線**，即可從主畫面搜尋您的連線。被索引的只有名稱與位址——也就是清單上已經顯示的那兩行——關閉後它們會被移除。它預設關閉，因為不必開啟本應用程式即可讀取該索引。

**捷徑與 Siri。** 三個動作：*連線至伺服器*、*在伺服器上執行指令片段*、*中斷所有工作階段*。指令片段是否一到就執行，取決於片段本身的設定，而不是捷徑，因此自動化不會讓原本點按時不會執行的東西執行起來。

**接力。** 當某個工作階段顯示在畫面上時，您的另一台裝置會提議繼續它。SSH 工作階段無法搬移——連線及其金鑰都在這裡——因此「繼續」會向同一台伺服器開啟一個新的工作階段。被交接的只是「哪一條連線」，別無其他。

## 助理

助理用來解釋一道指令、一個錯誤或一段輸出。在您完成設定之前它處於關閉狀態，而且它是本應用程式中唯一可能將文字傳送出去的功能。

**優先使用裝置端模型** 會在裝置支援時把一切留在本機。否則您需要填入提供者的基礎 URL、模型名稱與 API 金鑰，您送出的文字會依照您與該提供者之間的條款送達他們——而不是送給開發者，開發者在這件事上沒有任何伺服器。API 金鑰保存在本裝置的 Keychain 中。

在您提問之前不會送出任何內容，送出的也就是您所選取的內容。

<!-- topic: privacy -->
## 哪些內容留在本裝置上

沒有帳號、不需註冊、沒有分析統計。沒有任何內容被上傳，本應用程式也沒有可供上傳的伺服器。

- **私密金鑰與密碼** 存放在本裝置的 Keychain 中；在 Secure Enclave 中產生的金鑰則位於 Enclave 內部。它們絕不會被寫入連線清單、記錄檔或診斷檔案。
- **Cloudflare 權杖** 同樣是 Keychain 項目，且限定於它們所屬的主機名稱。
- **連線、畫面、指令片段與已知主機** 是一般的本機資料。
- **指令歷史** 預設關閉、僅存本機，關閉時即刪除。
- **診斷**——**匯出診斷資料** 所得到的檔案——不含指令、不含輸出、不含主機名稱、不含憑據。
- **iCloud 同步** 在本版本中無法使用。一切都留在本裝置上。
- **App 鎖定** 會在本應用程式之前加上密碼、Face ID 或 Touch ID；**在 App 切換器中隱藏內容** 則讓您的終端機不出現在 App 切換器的快照中。
- **備份** 是由您製作並保管的檔案。包含私密金鑰時，檔案會以您輸入的密碼加密——該密碼不儲存於任何地方，沒有它，任何人都無法開啟該備份，包括您自己。
- **刪除所有資料** 會清除一切：連線、金鑰、權杖、歷史、設定。

## 出問題的時候

**host key 變了。** 連線是被刻意拒絕的。在做任何其他事之前先弄清楚原因；若伺服器確實被重建過，請在 **設定 → 已知主機** 中刪除它的項目，然後接受新金鑰。

**Cloudflare 拒絕了。** 在該連線上開啟 **Access 診斷**。它會告訴您該主機名稱是否位於 Access 之後、它接受什麼，以及這裡的權杖是否仍然有效。

**身分驗證一直失敗。** 檢查使用者名稱——留空的使用者名稱會在連線時詢問，很容易順手接受了錯誤的預設值。若伺服器發問而不是接受密碼，請照它所問的作答；那些問題來自伺服器，而不是本應用程式。

**伺服器拒絕了代理轉發。** 許多伺服器都會（`AllowAgentForwarding no`），而工作階段本身照常可用——只是無法在對端為任何事情簽章。

**遠端轉發無法繫結。** 除非伺服器的 `sshd` 設定了 `GatewayPorts`，否則它只能監聽 `127.0.0.1`。這項拒絕來自伺服器。

**畫面：伺服器只提供 VeNCrypt TLS。** 這些子類型不受支援，本應用程式會據實說明，而不會改用更弱的協商方式。

**其他情況。** **設定 → 匯出診斷資料** 會給出一個檔案，描述本應用程式做了什麼——版本、時間、錯誤類別——其中不含指令、輸出、主機名稱或憑據。
