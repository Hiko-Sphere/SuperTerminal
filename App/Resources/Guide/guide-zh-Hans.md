## 第一次连接

在连接列表中点按 **+**，粘贴地址即可。它会被自动拆解：`deploy@build.example.com:2222`、`ssh://deploy@host:2222` 和 `[2001:db8::1]:22` 都可以。端口留空表示 22。用户名留空则在每次打开连接时询问——对于多人使用不同账号登录的机器，这正是您需要的。

第一次连接时，服务器会向您出示它的 host key fingerprint，在您确认之前不会发生任何事。这项核对由您完成——见 **Host key**。确认之后它会被记住。

连接界面上的其他内容都有可用的默认值。您可以只填一个地址就保存连接，其余的以后再说。

<!-- topic: signing-in -->
## 登录

Apex Terminal 会按服务器期待的顺序提供您已配置的凭据，并在必要时改为询问：

- **私钥。** 在 **私钥** 中选择一把。密钥从不离开设备。
- **密码。** 打开 **提供密码**。把字段留空，就改为每次询问，而不是存储它。
- **服务器提出的问题。** 有些服务器不接受密码，而是发问——一次性验证码、令牌、因过期而必须更换的密码。Apex Terminal 会逐字显示服务器所问的内容，并把您输入的内容原样送回。这些回答从不存储。
- **什么都没配置。** 既没有密钥也没有选择密码时，本应用会询问服务器接受什么，并只就服务器真正接受的方式向您提示。

如果您的密钥旁边有 OpenSSH 证书，会先提供证书、再提供裸密钥，于是信任您的 CA 的服务器无需见过您的密钥就能放行。

<!-- topic: keys -->
## 本设备上的密钥

**设置 → 密钥** 是它们所在的位置。您可以生成密钥，也可以导入密钥。

生成时有一个真正重要的选择：

| 类型 | 私钥部分存放在哪里 | 取舍 |
| --- | --- | --- |
| Ed25519 或 ECDSA P-256 | 本设备的 Keychain | 可以备份，并通过备份文件复制到另一台设备 |
| Secure Enclave（P-256） | Secure Enclave 内部 | 无法导出、无法备份、无法复制——本应用不能，任何人都不能。设备一旦丢失，密钥即随之消失 |

Secure Enclave 密钥可以设置为**每一次签名**都需要 Face ID 或 Touch ID，也就是每一次使用它的连接。这是硬件所能提供的最强选项，也是保护重要目标的那把密钥应当选择的方式。

导入支持 OpenSSH 私钥，包括受口令保护的密钥（`ssh-rsa`、`ecdsa-sha2-nistp256`、`ssh-ed25519`）。口令只用于解开密钥这一次，不会被保留。

每把密钥的公钥部分都可以从密钥列表复制，这正是您要粘贴到服务器 `authorized_keys` 中的内容。

<!-- topic: agent-forwarding -->
## 让服务器使用您的密钥

代理转发——连接上的 **让此服务器使用我的密钥**——允许运行在服务器上的程序请求*您的设备*进行签名，于是您可以从这台服务器的 shell 中访问第二台服务器或某个 Git 远端。密钥本身不会去往任何地方。

它默认关闭，对于不由您掌控的机器也应保持关闭。在您连接期间，该服务器上以 root 身份运行的任何程序都可以请求您的设备签名，用途不限，包括连接到您使用的其他服务器。它读不到密钥，断开连接的那一刻签名即停止——但只要会话还开着，那台服务器就能以您的身份行事。

只有该连接已在使用的那把密钥会被提供。设备上的其他任何东西都无法触及。

<!-- topic: host-keys -->
## Host key 与它变更时的含义

每台服务器都用 host key 证明自己的身份。首次连接时没有任何可比对的对象，因此本应用会向您显示 fingerprint 并由您决定——把它与服务器管理者公布的内容核对，或与您已经信任的机器上 `ssh-keyscan` 的输出核对。

此后该密钥会被记入 **设置 → 已知主机**，而密钥发生变化的服务器会被**拒绝**。连接会在您的密码或密钥被提供之前停止。没有任何设置可以跳过这项检查。

密钥变更有两种常见原因：服务器被重建了，或者您看到的 fingerprint 属于别人。Apex Terminal 无法分辨这两者，也不会猜测。如果您确知服务器被重建，请在 **已知主机** 中删除旧条目，然后有意识地接受新密钥。

**受信任的颁发机构** 是这件事的另一半。添加某个 CA 的公钥之后，由它签发的每一把 host key 都会被接受，无需逐台主机决定——这是运维一整片机群而不积累一堆 fingerprint 的标准做法。

<!-- topic: cloudflare -->
## Cloudflare Access 与 Tunnel

通过 Cloudflare Tunnel 发布的服务器没有可供连接的开放 SSH 端口。打开 **通过 Cloudflare Tunnel**，Apex Terminal 会自行建立隧道——无需安装 `cloudflared`，也无需在旁边运行任何东西。

两种登录方式：

- **浏览器登录** 会在系统浏览器中打开 Cloudflare Access，您在那里使用贵组织所用的身份提供方。令牌以密封形式返回本应用，存放在本设备的 Keychain 中，且只用于该主机名。
- **服务令牌** 无需浏览器即可登录。在 Cloudflare Zero Trust → Access → Service Auth 中创建，并在该应用程序的策略中允许它。它保存在 Keychain 中，从不同步，并随连接一起删除。

Cloudflare 连接失败时，错误通常来自 Access 而不是 SSH，因此 **Access 诊断** 会直接针对该主机名进行检查，并告诉您它发现了什么：该主机名是否确实位于 Access 之后、该应用程序提供哪些登录方式、本设备持有的令牌是否仍然有效以及何时过期。它还可以只退出该应用程序的登录，而不影响您其他的 Cloudflare 会话。

**设置 → 退出所有 Cloudflare Access 应用** 会清除设备上的每一个令牌。

<!-- topic: jump-hosts -->
## 经由另一台服务器抵达

无法直接访问的服务器，可以经由能访问的服务器抵达。在连接上添加跳板机，它们会按顺序使用：先连接第一台，通过它打开到第二台的通道，依此类推直到目标。

每一跳都以自己的身份进行验证，使用各自的密钥或密码；每一跳的 host key 都与其他任何连接一样接受检查。不会因为某条连接只是中间环节就放松任何要求。

<!-- topic: terminal -->
## 终端

完整的 xterm-256color 仿真、真彩色、宽字符与组合字符，回滚行数可在 **设置 → 终端** 中设定。

在手机上，或在没有硬件键盘的 iPad 上，键盘上方的一行提供触摸键盘没有的按键：Control、Escape、Tab、方向键。点按 **Control** 会为下一个按键锁定，因此先按 Control 再按 C 会发送 `^C`。长按可持续按住。

- **选择文本**：触摸并按住；可通过两端的手柄扩展选区。
- **查找**：⌘F，或从工具栏进入——匹配项会高亮，并可逐个跳转。
- **粘贴**：多于一行的文本在发送前会请求确认，以免误入剪贴板的内容执行了您没读过的命令。该检查可以关闭。
- **字号**：⌘+（或 ⌘=）与 ⌘−，⌘0 恢复原始大小。
- **主题** 以及跟随系统的浅色/深色设置在 **设置 → 外观** 中。

如果连接中断且 **自动重新连接** 处于开启状态，网络恢复后它会自行恢复。您的回滚内容会保留，新的 shell 会在终端中被标出——它从头开始，位于主目录，没有任何正在运行的程序。看起来丢了工作的 shell 其实没丢：那些工作在旧连接上，而旧连接已经不在了。

<!-- topic: panes -->
## 一屏之内的多个窗格

一个会话可以被拆分，从而同时看到不止一样东西——两个 shell、一个 shell 加一个远程屏幕、四个 shell，视空间而定。

| 操作 | 按键 |
| --- | --- |
| 向右拆分 | ⌘D |
| 向下拆分 | ⇧⌘D |
| 关闭此窗格 | ⌥⌘W |
| 下一个窗格 | ⌥⌘] |
| 上一个窗格 | ⌥⌘[ |

没有硬件键盘时，同样的命令位于工具栏的 **会话** 菜单中。手机与 iPad 上都可以拆分；在手机上，各个窗格共用一个工具栏，它属于当前获得焦点的那个窗格。拖动两个窗格之间的分隔线可以改变空间分配；窗格不会被拖到消失。获得焦点的窗格带有强调色边框，VoiceOver 也会朗读它处于焦点状态。

在列表中点按某个连接会替换当前布局，而不是往里添加——拆分是一个有意的动作，不该因为您打开了什么就自动发生。

<!-- topic: tmux -->
## tmux

为某条连接打开 **连接到 tmux**，之后打开它就会接入服务器上的 tmux 会话，而不是启动一个普通 shell；若该会话不存在则会被创建。断开连接后，其中运行的内容会继续运行；换一台设备再打开这条连接，你会看到它停在你离开时的样子。

在 tmux 会话里，*服务器* 拥有布局。屏幕上的窗格就是 tmux 自己的窗口与窗格，按 tmux 所说的位置绘制，因此你在笔记本电脑上排好的布局，在这里看到的就是同一个。工具栏中的 **tmux** 菜单可以列出窗口、新建窗口、拆分与关闭窗格，以及断开但保留。

- **断开但保留** 会让一切继续运行。它与意外掉线不同，也是结束一次使用的正常方式。
- 会话名称在该连接的设置中。留空表示 `apex`；填写名称可以把不同的工作分开。
- 服务器上必须安装 tmux。如果没有，本应用会如实说明，而不会把你丢进一个你并未要求的 shell。

本应用自己的分窗（⌘D）用于普通会话。在 tmux 中请使用 tmux 的——两者同时决定同一套布局只会互相打架，而最终是服务器说了算。

<!-- topic: sessions -->
## 会话与被复用的连接

您打开的每条连接都是一个会话，列在边栏中，并可用 ⌘1 至 ⌘9、⌘] 和 ⌘[ 访问。⌘W 关闭当前正在看的那一个。

在一台已连接的服务器上打开第二个会话，并不会建立第二条连接。只要各项条件一致——相同的主机与端口、相同的用户名、相同的密钥或密码、相同的跳板机、相同的隧道——Apex Terminal 就会复用已经建立的那一条。这意味着一次身份验证而非两次、一次 Face ID 而非两次，服务器也只需记录一条连接。同一台服务器上的 shell、文件浏览器和端口转发共用它。

上述任何一项发生变化，您就会得到一条独立的连接，因为以另一个身份验证过的连接并不是同一条连接。当最后一个使用者关闭后，它会被短暂保留以备您立刻回来，随后关闭。

<!-- topic: files -->
## 文件

每条连接都带有文件浏览器：SFTP 走在同一条连接上，无需另行登录。

- 浏览、按名称/大小/日期排序，并用工具栏返回上一级。
- **上传** 可来自 iOS 能访问的任何位置；**下载** 到“文件”App；**快速查看** 让您无需先下载即可阅读。
- 重命名、删除、新建文件夹并编辑权限——权限同时以读/写/执行网格和八进制数字显示，两者保持同步。
- 传输在一个可查看的队列中进行，逐个文件显示进度，切换文件夹也不会中断。

为某条连接打开 **在“文件”App 中显示**，该服务器就会出现在“文件”App 中，与 iCloud 云盘并列——于是任何能打开文稿的 App 都能打开您服务器上的文稿。相应的凭据保存在本应用自己的 Keychain 访问组中；该扩展获得的权限不会超过它所需要的。

<!-- topic: forwarding -->
## 端口转发

连接上的 **端口转发** 提供 `ssh` 所具备的三种转发，含义完全相同：

| 类型 | 作用 |
| --- | --- |
| 本地 | 把本设备上的一个端口转发到服务器能访问的某个地址 |
| 远程 | 把服务器上的一个端口转发回本设备能访问的某个地址 |
| 动态（SOCKS5） | 在本设备上提供 SOCKS5 代理，流量经由服务器 |

本地转发与动态转发在本设备上监听，因此设备上的任何程序——浏览器、您正在测试的 App——都能使用它们。远程转发在服务器上监听；除非其 `sshd` 设置了 `GatewayPorts`，否则它只能绑定 `127.0.0.1`，请求绑定其他地址会被服务器拒绝，而不是被本应用拒绝。端口填 0 表示由服务器选择，转发建立后会显示它所选的端口。

每条转发都会显示它是否在监听、绑定在哪里、当前有多少条连接经过它，以及已发送和接收了多少数据。转发只在本应用运行且该连接打开时有效。

<!-- topic: screens -->
## 远程屏幕

屏幕是通过 VNC 呈现的完整桌面，并且可以走在 SSH 连接内部，因此无需向网络暴露任何东西。**连接方式** 提供三种路径：**通过 SSH**（在您已有的连接内部开一个通道）、**Cloudflare**（经由隧道，与终端相同），或对已经可以直接访问的服务器使用 **直连**。

触摸操作符合直觉：点按即单击，按住即拖动，双指滚动，捏合可放大查看大桌面的某个角落——放大之后，双指改为平移画面。硬件键盘与触控板或鼠标按其本来的方式工作。

身份验证遵循服务器所提供的方式——经典 VNC 密码，或 VeNCrypt 的 plain 与 VNC 认证子类型。只有当服务器需要登录到某个账户时才需要用户名：共享屏幕的 Mac，或使用 VeNCrypt 的服务器。密码保存在本设备的 Keychain 中，从不出现在屏幕的记录里；留空则在打开屏幕时询问。

不支持 VeNCrypt 自带的 TLS 子类型。当服务器只提供这些时，本应用会如实说明，而不会退回到更弱的方式。

## 片段与命令面板

片段就是您不想再重复输入的命令。在 **设置 → 片段** 中保存，之后在任何会话中一点即用。

⌘K 打开命令面板，它会同时搜索您已打开的会话、您的连接、片段和每一个操作。输入其中任意一项的几个字母；回车即执行第一条结果。

**记录命令历史** 默认关闭。开启后，您运行过的命令会被再次提供给您；关闭则会删除已记录的内容。它只存储在本设备上，从不同步。

<!-- topic: assistant -->
## 助手

助手用来解释一条命令、一个错误或一段输出。在您完成设置之前它处于关闭状态，而且它是本应用中唯一可能把文本发送出去的功能。

**优先使用设备端模型** 会在设备支持时把一切留在本地。否则您需要填写提供方的基础 URL、模型名称和 API 密钥，您发送的文本会依照您与该提供方之间的条款送达他们——而不是送给开发者，开发者在这件事上没有任何服务器。API 密钥保存在本设备的 Keychain 中。

在您提问之前不会发送任何内容，发送的也就是您所选中的内容。

<!-- topic: privacy -->
## 哪些内容留在本设备上

没有账户、无需注册、没有分析统计。没有任何内容被上传，本应用也没有可供上传的服务器。

- **私钥与密码** 存放在本设备的 Keychain 中；在 Secure Enclave 中生成的密钥则位于 Enclave 内部。它们从不被写入连接列表、日志或诊断文件。
- **Cloudflare 令牌** 同样是 Keychain 项目，且限定于它们所属的主机名。
- **连接、屏幕、片段和已知主机** 是普通的本地数据。
- **命令历史** 默认关闭、仅存本地，关闭时即删除。
- **诊断**——**导出诊断信息** 得到的文件——不含命令、不含输出、不含主机名、不含凭据。
- **iCloud 同步** 在本版本中不可用。一切都留在本设备上。
- **应用锁** 会在本应用之前加上密码、Face ID 或 Touch ID；**在应用切换器中隐藏内容** 则让您的终端不出现在应用切换器的快照中。
- **备份** 是由您制作并保管的文件。包含私钥时，文件会用您输入的密码加密——该密码不存储在任何地方，没有它，任何人都无法打开该备份，包括您自己。
- **删除所有数据** 会清除一切：连接、密钥、令牌、历史、设置。

<!-- topic: troubleshooting -->
## 出问题的时候

**host key 变了。** 连接是被有意拒绝的。在做任何其他事情之前先弄清原因；如果服务器确实被重建过，请在 **设置 → 已知主机** 中删除它的条目，然后接受新密钥。

**Cloudflare 拒绝了。** 在该连接上打开 **Access 诊断**。它会告诉您该主机名是否位于 Access 之后、它接受什么，以及这里的令牌是否仍然有效。

**身份验证一直失败。** 检查用户名——留空的用户名会在连接时询问，很容易顺手接受了错误的默认值。如果服务器发问而不是接受密码，请照它所问的作答；那些问题来自服务器，而不是本应用。

**服务器拒绝了代理转发。** 很多服务器都会（`AllowAgentForwarding no`），而会话本身照常可用——只是无法在对端为任何事情签名。

**远程转发无法绑定。** 除非服务器的 `sshd` 设置了 `GatewayPorts`，否则它只能监听 `127.0.0.1`。这项拒绝来自服务器。

**屏幕：服务器只提供 VeNCrypt TLS。** 这些子类型不受支持，本应用会如实说明，而不会改用更弱的协商方式。

**其他情况。** **设置 → 导出诊断信息** 会给出一个文件，描述本应用做了什么——版本、时间、错误类别——其中不含命令、输出、主机名或凭据。
