## 描述

上限 4000 字符。

### Description

```
Apex Terminal 是一个为 iPhone 和 iPad 写的 SSH 客户端。它在你自己的服务器上打开真正的交互式会话，分配真实的 PTY，再用它自带的终端模拟器把回来的内容画出来。

命令跑在你自己的远程主机上。没有账号要注册，没有我们运营的后台，也没有任何需要付费的东西。

一条连接，而不是四条

在同一台服务器上打开终端、文件浏览、远程桌面和端口转发，你付出的是一次 TCP 连接、一次密钥交换、一次认证、一次生物识别提示。它们是同一条 SSH 连接上的四条通道，不是四次独立登录。

在移动网络下，四次握手就是四次可能失败的机会。这里只有一次。

终端，不是"差不多的终端"

· 24 位真彩色与 256 色，两种 SGR 写法都认
· 备用屏幕缓冲：退出 vim 或 less，shell 原样还在，历史不会被冲掉
· sixel 图像——gnuplot、img2sixel 画出来的是真的图
· 鼠标上报，三种模式，带修饰键、滚轮与拖拽
· 中日韩文字、emoji、组合字符的字宽正确，取自 Unicode 官方表
· 改变宽度时重排，回滚缓冲支持块选择，并可全文搜索
· OSC 7、OSC 52、OSC 133——工作目录、剪贴板、shell 集成
· 任意等宽字体，字号与行高自己定

文件，不必再开一个 App

用同一条 SSH 连接浏览服务器上的文件：上传、下载、重命名、新建目录、改权限。可以同时打开多个远程目录——同一台服务器开两个，或者两台服务器并排放在 iPad 上。还能把一个连接挂进"文件"App，在 iOS 任何地方都能取用。

看得见的隧道

本地、远程、动态（SOCKS5）转发都支持。规则随连接保存、随连接启动，每条规则实时显示发出字节、收到字节、当前连接数和累计连接数。起不来的转发会直接告诉你原因，并且点名是哪个端口。

把 tmux 当协议来说

Apex Terminal 说的是 tmux 自己的控制协议，所以 tmux 是它驱动的对象，而不是它去猜的一堆文本。给连接打开"接入 tmux"，打开时就进到指定的会话里。断开、把 iPad 放下、再接回来——窗口、窗格和上面的输出都还在。

顺带把桌面也接上

远程桌面走 VNC，就在同一个 App 里，通过同一条 SSH 连接抵达——不必对公网暴露任何端口。点一下就是一次真实的鼠标点击，辅助键行补上触摸键盘没有的那些键，本地剪贴板也能送过去。

密钥留在你放它的地方

可以在设备上生成 Ed25519 或 ECDSA P-256 密钥。也可以让它直接在 Secure Enclave 里生成：私钥在专用硬件内部产生，从不在硬件之外存在，导不出、进不了备份、也搬不到别的设备——而它照样能登录一台未经改动的 OpenSSH 服务器。已有的密钥可以导入，带口令的也行。

第一次连到一台服务器时，它的指纹会摆在你面前等你确认。之后如果这台服务器的密钥变了，那是硬性中止，不是耸耸肩放过去。如果你的组织用 CA 签主机密钥，那就信任一次 CA，从此不用再核对指纹。

此外还有：OpenSSH 用户证书与主机证书、经堡垒机的 ProxyJump、由设备本身充当 agent 的转发、带 PAM 或一次性验证码的服务器，以及在服务器支持时使用的后量子混合密钥交换。

为 iPad 而做

分屏之后，一边盯日志一边干活；每个窗格都是完整会话，各有各的控制。会话可以开在第二个窗口里。外接键盘可以直达：新建连接、命令面板、上一个/下一个会话、按编号切换、关闭、调字号——而 Command 键永远不会被转发给远程主机。

默认安静

没有统计、没有埋点、没有崩溃收集、没有广告标识符，也没有任何这类第三方 SDK。命令历史默认关闭，你不开它就不记录。复制走的文本会从剪贴板过期。服务器上的程序要写你的剪贴板必须先经你允许，读则一律拒绝。App 本身也可以用一道自己的密码锁上。

需要 iOS 或 iPadOS 17.0 及以上。服务器由你提供，这个 App 负责连上去。
```

## App Review Notes

审核说明只提交一份，请使用[英文版](APP_STORE_METADATA_EN.md)方框中的内容——审核人员读的是英文。这份中文对照是给项目方核对用的：确认审核说明里的每一句，都是你愿意为之负责的。

要点对照：

* **这是什么**：SSH 客户端。会话里看到的一切都来自用户自己的远程主机；App 自己不执行命令，也不经由我们的任何服务器中转。无账号、无后台、无内购。
* **怎么测**：任意一台能连上的 SSH 服务器即可（Mac 上打开"远程登录"就够）。含密码与密钥两条路径、主机密钥指纹确认、SFTP 浏览、"文件"App 集成、端口转发、tmux 接入、VNC 屏幕的具体步骤。
* **权限**：Face ID / Touch ID 只用于两件用户自己开启的可选事项（应用锁、用生物识别保护的私钥），都不是使用前提。首次连接同网段服务器时 iOS 可能请求本地网络权限——那就是 SSH 连接本身。
* **在二进制里但没有对外宣传的功能**（对应指南 2.3.1，必须逐项说明）：Cloudflare Tunnel / Access 连接、macOS 屏幕共享登录与 VeNCrypt、中日韩输入法在终端里的组合输入、iCloud 同步、助理、Mac Catalyst、快捷指令与 Handoff。每一项都写明了为什么没有宣传。
* **隐私**：无统计、无埋点、无广告标识符、无采集型第三方 SDK。连接、密钥、片段、已知主机都在设备上；私钥在钥匙串（带明确保护等级）或 Secure Enclave 里，App 不显示也不传输。
* **内容**：显示的是用户自己服务器送来的内容，App 自身除界面外没有内容，也没有浏览或发现第三方内容的入口。

## 加密与出口合规

**这题由提交者作答，不是由我们代答。** 工程没有设置 `ITSAppUsesNonExemptEncryption`，提交时 App Store Connect 会问。

草拟理由（需对照 `docs/EXPORT_COMPLIANCE.md` 并经律师确认）：

> 本应用使用加密，且全部为标准的、公开发布的密码学——SSH（RFC 4251–4254）、隧道连接下层的 TLS，以及系统自身的钥匙串与 Secure Enclave——用途是向用户自己控制的服务器进行认证并保护该连接。未实现任何自研或非标准密码学。这通常落入"仅使用标准加密进行认证与安全通信"的豁免情形。

请认真作答，不要一路点过去：部分司法辖区即使适用豁免，仍需提交年度自分类报告。
