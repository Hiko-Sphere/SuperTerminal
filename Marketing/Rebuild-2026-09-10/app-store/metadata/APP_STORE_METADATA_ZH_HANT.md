## 描述

上限 4000 字元。

### Description

```
Apex Terminal 是一個寫給 iPhone 和 iPad 的 SSH 用戶端。它在你自己的伺服器上開一個真正的互動式工作階段，配置真正的 PTY，再用它自己的終端機模擬器把回來的內容畫出來。

指令跑在你自己的遠端主機上。沒有帳號要註冊，沒有我們營運的後端，也沒有任何要付費的東西。

一條連線，而不是四條

在同一台伺服器上開終端機、檔案瀏覽、遠端桌面和連接埠轉送，你付出的是一次 TCP 連線、一次金鑰交換、一次驗證、一次生物辨識。它們是同一條 SSH 連線上的四個通道，不是四次各自登入。

在行動網路下，四次交握就是四次可能失敗的機會。這裡只有一次。

終端機，不是「差不多的終端機」

· 24 位元全彩與 256 色，兩種 SGR 寫法都認得
· 備用畫面緩衝：離開 vim 或 less，shell 還是原來的樣子，歷史不會被洗掉
· sixel 圖形——gnuplot、img2sixel 畫出來的是真的圖
· 滑鼠回報，三種模式，含修飾鍵、滾輪與拖曳
· 中日韓文字、emoji、組合字元的字寬正確，取自 Unicode 官方表格
· 改變寬度時重新排版，回捲緩衝支援區塊選取，並可全文搜尋
· OSC 7、OSC 52、OSC 133——工作目錄、剪貼簿、shell 整合
· 任何等寬字型都能用，字級與行高自己決定

檔案，不必再開一個 App

用同一條 SSH 連線瀏覽伺服器上的檔案：上傳、下載、更名、新增資料夾、改權限。可以同時開好幾個遠端資料夾——同一台開兩個，或者兩台並排放在 iPad 上。也能把一條連線掛進「檔案」App，在 iOS 任何地方取用。

看得見的通道

本機、遠端、動態（SOCKS5）轉送都支援。規則隨連線儲存、隨連線啟動，每一條即時顯示送出位元組、收到位元組、目前連線數與累計連線數。起不來的轉送會直接說明原因，並且點名是哪個連接埠。

把 tmux 當成協定來說

Apex Terminal 說的是 tmux 自己的控制協定，所以 tmux 是它驅動的對象，而不是它去猜的一堆文字。替連線打開「接上 tmux」，開啟時就進到指定的工作階段裡。離線、把 iPad 放下、再接回來——視窗、窗格和上面的輸出都還在。

順便把桌面也接上

遠端桌面走 VNC，就在同一個 App 裡，透過同一條 SSH 連線抵達——不必對外開放任何連接埠。點一下就是一次真正的滑鼠點擊，輔助鍵列補上觸控鍵盤沒有的那些鍵，本機剪貼簿也送得過去。

金鑰留在你放它的地方

可以在裝置上產生 Ed25519 或 ECDSA P-256 金鑰。也可以讓它直接在 Secure Enclave 裡產生：私鑰在專用硬體內部誕生，從不在硬體之外存在，匯不出、進不了備份、也搬不到別的裝置——而它照樣登入一台未經改動的 OpenSSH 伺服器。已經有的金鑰可以匯入，帶通行碼的也行。

第一次連到一台伺服器時，它的指紋會擺在你面前等你確認。之後如果這台伺服器的金鑰變了，那是硬性中止，不是聳聳肩放過去。如果你的組織用 CA 簽主機金鑰，那就信任一次 CA，從此不必再核對指紋。

另外還有：OpenSSH 使用者憑證與主機憑證、經跳板機的 ProxyJump、由裝置本身充當 agent 的轉送、帶 PAM 或一次性驗證碼的伺服器，以及在伺服器支援時使用的後量子混合金鑰交換。

為 iPad 而做

分割之後，一邊盯著日誌一邊做事；每個窗格都是完整的工作階段，各有各的控制項。工作階段可以開在第二個視窗裡。外接鍵盤可以直達：新增連線、指令面板、上一個／下一個工作階段、依編號切換、關閉、調整字級——而 Command 鍵永遠不會被轉送給遠端主機。

預設安靜

沒有統計、沒有埋點、沒有當機回報、沒有廣告識別碼，也沒有任何這一類的第三方 SDK。指令紀錄預設關閉，你不開它就不會記。複製走的文字會從剪貼簿過期。伺服器上的程式要寫你的剪貼簿必須先經你允許，讀則一律拒絕。App 本身也能用一道自己的密碼鎖上。

需要 iOS 或 iPadOS 17.0 以上。伺服器由你提供，這個 App 負責連上去。
```

## App Review Notes

審核說明只送一份，請使用[英文版](APP_STORE_METADATA_EN.md)方框裡的內容——審核人員讀的是英文。這份繁中對照是給專案方核對用的：確認審核說明裡的每一句，都是你願意負責的。

重點對照：

* **這是什麼**：SSH 用戶端。工作階段裡看到的一切都來自使用者自己的遠端主機；App 自己不執行指令，也不經由我們的任何伺服器轉送。無帳號、無後端、無 App 內購買。
* **怎麼測**：任何一台連得到的 SSH 伺服器都行（Mac 上打開「遠端登入」就夠）。含密碼與金鑰兩條路徑、主機金鑰指紋確認、SFTP 瀏覽、「檔案」App 整合、連接埠轉送、tmux 接入、VNC 畫面的具體步驟。
* **權限**：Face ID / Touch ID 只用於兩件使用者自己開啟的選用功能（App 鎖定、以生物辨識保護的私鑰），兩者都不是使用前提。首次連線到同網段伺服器時 iOS 可能要求本機網路權限——那就是 SSH 連線本身。
* **在二進位檔裡但沒有對外宣傳的功能**（對應指南 2.3.1，必須逐項說明）：Cloudflare Tunnel / Access 連線、macOS 螢幕共享登入與 VeNCrypt、中日韓輸入法在終端機裡的組字、iCloud 同步、助理、Mac Catalyst、捷徑與 Handoff。每一項都寫明了為什麼沒有宣傳。
* **隱私**：無統計、無埋點、無廣告識別碼、無會蒐集資料的第三方 SDK。連線、金鑰、片段與已知主機都在裝置上；私鑰放在鑰匙圈（帶明確保護等級）或 Secure Enclave 裡，App 不顯示也不傳輸。
* **內容**：顯示的是使用者自己伺服器送來的內容，App 本身除了介面之外沒有內容，也沒有瀏覽或探索第三方內容的入口。

## 加密與出口合規

**這題由送審者作答，不是由我們代答。** 專案沒有設定 `ITSAppUsesNonExemptEncryption`，送審時 App Store Connect 會問。

草擬理由（需對照 `docs/EXPORT_COMPLIANCE.md` 並經律師確認）：

> 本 App 使用加密，且全部是標準的、公開發表的密碼學——SSH（RFC 4251–4254）、通道連線底層的 TLS，以及系統本身的鑰匙圈與 Secure Enclave——用途是向使用者自己掌控的伺服器進行驗證，並保護該連線。未實作任何自有或非標準的密碼學。這通常落在「僅使用標準加密進行驗證與安全通訊」的豁免情形。

請認真作答，不要一路點過去：部分司法管轄區即使適用豁免，仍需提交年度自我分類報告。
